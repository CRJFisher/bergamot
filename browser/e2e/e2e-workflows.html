Bergamot — E2E Test Workflows

What the Playwright cross-tab suite (browser/e2e) drives and asserts. Each test loads the real MV3 extension into a persistent Chromium context and verifies the captured visit records against a mock PKM server that stands in for the VS Code backend.

Harness architecture

Every test shares this setup. The extension is built with a mock server port baked in (build:test), loaded via launchPersistentContext, and driven headless. Visits flow page → content script → background service worker → mock server, which is the assertion oracle.

1. Basic capture passing basic_capture.spec.ts

A single page load is captured as a visit with a session id.

sequenceDiagram participant T as Test participant P as Page A participant CS as Content script participant BG as Background participant M as Mock server T->>P: newPage + goto /page-a P->>CS: DOMContentLoaded CS->>BG: getReferrer BG-->>CS: { group_id, referrer:"" } CS->>M: POST /visit { url:/page-a, group_id } T->>M: wait_for_visit(url ~ /page-a) Note over T: assert visit.url, visit.group_id, page_loaded_at

2. New tab via target="_blank" driving via Phase 3.1 cross_tab.spec.ts

Opening a link in a new tab must keep the new tab in the opener's session and record the opener as referrer.

sequenceDiagram participant T as Test participant A as Tab A (/page-a) participant B as Tab B (/page-b) participant BG as Background participant M as Mock server T->>A: goto /page-a A->>M: POST /visit { /page-a, group_id:G } T->>A: click a[target=_blank] Note over BG: onCreatedNavigationTarget
B inherits G from opener A A-->>B: open /page-b (new tab) B->>BG: getReferrer BG-->>B: { group_id:G, referrer:/page-a } B->>M: POST /visit { /page-b, group_id:G, referrer:/page-a } Note over T: assert visit_b.group_id == G
assert visit_b.referrer ~ /page-a

3. New tab via window.open driving via Phase 3.1 cross_tab.spec.ts

A programmatically opened tab stays in the opener's session.

sequenceDiagram participant T as Test participant A as Tab A (/page-a) participant D as Tab D (/page-d) participant BG as Background participant M as Mock server T->>A: goto /page-a A->>M: POST /visit { /page-a, group_id:G } T->>A: click button → window.open('/page-d') Note over BG: onCreatedNavigationTarget → D inherits G A-->>D: open /page-d D->>M: POST /visit { /page-d, group_id:G } Note over T: assert visit_d.group_id == G

4. Same-tab navigation driving via Phase 3.1 cross_tab.spec.ts

Following a link in place keeps the session and chains the referrer.

sequenceDiagram participant T as Test participant P as Tab (A → C) participant BG as Background participant M as Mock server T->>P: goto /page-a P->>M: POST /visit { /page-a, group_id:G } T->>P: click a → /page-c (same tab) Note over BG: webNavigation.onCommitted
previous_url = /page-a, group_id stays G P->>BG: getReferrer BG-->>P: { group_id:G, referrer:/page-a } P->>M: POST /visit { /page-c, group_id:G, referrer:/page-a } Note over T: assert visit_c.group_id == G
assert visit_c.referrer ~ /page-a

5. SPA history navigation driving via Phase 3.1 spa_navigation.spec.ts

history.pushState sub-navigations are captured in the same session. The page's pushState runs in the main world, so detection moves to the background via webNavigation.onHistoryStateUpdated, which then asks the content script to capture.

sequenceDiagram participant T as Test participant P as Page /spa participant BG as Background participant M as Mock server T->>P: goto /spa P->>M: POST /visit { /spa, group_id:G } T->>P: click → history.pushState('/spa/sub1') Note over BG: webNavigation.onHistoryStateUpdated BG->>P: captureVisit('/spa/sub1') P->>M: POST /visit { /spa/sub1, group_id:G } Note over T: assert sub1.group_id == G (and sub2)
