The first two pages found where Bergamot's topic-cluster surfaces fall short: clusters are invisible inside the IDE, their IDs vanish on every rebuild, there's no way to search them in plain language, no signal that they're fresh, and every real task drops down to a command line. This page turns those findings into a build list. Each gap becomes one proposal card carrying what it does, roughly how much work it is (small, medium, or large), and which pain it removes. The cards start pre-sorted into three priority lanes — do now, do next, do later — reflecting how badly each gap blocks a real user against how much it costs to fix. You can drag a card between lanes to re-rank it; each lane keeps a running count and total effort so you can see when a lane is overloaded, then copy the agreed plan out as markdown.
