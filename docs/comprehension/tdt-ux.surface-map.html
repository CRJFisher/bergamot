Bergamot · Topic clusters

Four ways into the topics your browsing reveals

Temporal Topic Detection 4 entry surfaces 5 UX dimensions

Bergamot watches which pages you browse (only the addresses, never the content) and quietly groups them into topics — the projects you're actually spending time on. It calls each group a "cluster." Once clustering runs, there are exactly four doors into those clusters: a command you type into VS Code, a timer that rebuilds them once a day, internal web addresses the extension calls itself, and a Claude Code skill you drive from prompts. This page lays the four doors side by side, answering plain questions for each — who opens it, how, what they see, and what they can do next — then grades all four on five things a person actually cares about: can I find it, can I act on what I see, do I know if it's fresh, does it plug into my notes, and is it easy for an AI agent to use.

Who opens it · how · what they see · what's next

Command

Detect topic clusters

bergamot.tdt.rebuildClusters

Who invokes
You, from the VS Code Command Palette.
How
bergamot.tdt.rebuildClusters → "Bergamot: Detect topic clusters from browsing".
What they see
A progress notification, then a result toast: cluster count, visit count, excluded origins.
What's next
Nothing — the toast is terminal. It clears and leaves no trace.
Scheduler

Automatic rebuild

ClusterScheduler

Who invokes
Nobody — it fires itself on a timer.
How
Default 24h cadence; first tick 60s after activation.
What they see
Nothing user-visible; failures are logged silently in the Output panel.
What's next
Not applicable — no surface, no signal.
HTTP routes

Internal read routes

loopback server

Who invokes
The extension itself, or a programmatic caller.
How
Six internal endpoints: /query/clusters, /query/cluster, /query/clusters_for_page, /query/cluster_coverage, /query/visits_in_window, POST /cluster_control.
What they see
JSON.
What's next
Another HTTP call — the caller composes its own flow.
Skill

bergamot-clusters

Claude Code skill

Who invokes
Claude Code (an agent), driven by your prompts.
How
node …/bergamot_clusters.js <command>: recent, page, cluster, coverage, stub, suppress/rename/block.
What they see
Text output the agent reads and relays.
What's next
Stage a note stub into bergamot.staging/, or run a curation control.

The product-level gap

Not a per-door problem

Systemic gap

Freshness awareness and PKM integration are weak across every door — those two rows never rise above a half-disc anywhere. That makes them product-level gaps to close once, not four separate surface fixes — the augmentation proposals take these two rows first.
