📥 Page Processing

How a captured page becomes a stored record. Ingestion is now pure, lossless capture with zero LLM calls — the raw page is stored compressed alongside cheap metadata, and all interpretation (extraction, chunking, embedding, summarisation) moves to the RAG-prep pipeline.

capture → deterministic gate → store raw page + metadata  ·  (no LLM)

Page processing is the stage inside the VS Code extension that turns a captured page into a durable record. The organising idea: separate capture from interpretation. Capture is dumb, deterministic, and lossless — it persists the raw page bytes (compressed) and a little cheap metadata, and makes no LLM calls at all. Everything intelligent — isolating the article, chunking, embedding, summarising — is the job of the RAG-prep pipeline, which reads the stored raw pages on its own schedule. This page describes the target design (task-35); the "before" is shown for contrast only.

Why store the whole page? A page can never be re-captured — once you've left it, lossy extraction at ingest is an irreversible loss. Storing the raw page (zstd-compressed, a few hundred KB) is cheap and means the RAG pipeline can re-extract and re-chunk the entire corpus with better algorithms at any time. Capture preserves; the pipeline interprets.

3Target pipeline

Capture is a short, fully deterministic path. It decides keep/drop on cheap signals, pulls a little metadata straight from the HTML <head> (no main-content extraction), and persists the raw page compressed. No model is ever called.

Lossless capture

The raw page is stored zstd-compressed in DuckDB. Nothing is interpreted or thrown away, so the RAG pipeline can re-extract and re-chunk the whole corpus later with better algorithms.

Cheap metadata only

Title, site, author, published date and language come straight from the HTML <head> / Open-Graph tags — a trivial parse, not main-content extraction. Enough to browse and build the navigation tree.

Deterministic gate

No taxonomy, no model. Cheap signals — body size, link-density, empty/error pages, content-type — decide keep/drop. PDFs and non-HTML get a dedicated drop reason. Fully offline, fully testable.

Zero LLM, zero failure surface

Ingestion makes no network call and cannot fail on auth, prompt-length, or non-JSON. It is the cheapest, most robust path; all model cost moves to the RAG pipeline where it is gated.

4The stored record — PageCapture

One canonical record replaces webpage_analysis. It is the lossless capture plus the cheap metadata, keyed by page_session_id — the stable id the RAG pipeline's chunks will foreign-key to. The raw page is the durable source of truth for everything downstream.

5Where intelligence lives now — the RAG-prep pipeline

Everything the old ingestion did with an LLM moves to the RAG-prep pipeline (task-31), which reads stored raw pages and is free to re-run over the whole corpus. This is the clean home for it: extraction quality, chunk strategy, and embeddings should be tuned against the retrieval harness, not baked irreversibly into capture.

Interim search. Today whole-page embeddings are made at ingest, so semantic search works immediately. Capture-first removes that — search is produced by the RAG-prep pass. Until task-31 lands, either accept that captured pages are not yet searchable, or add a thin interim whole-page embedding at capture (local all-MiniLM, still no LLM) over cheaply tag-stripped text, to be superseded by chunked embeddings. This is a flagged decision, not yet baked in.

6Default model & cost

Ingest cost: zero

No LLM tokens, no network, no per-page model cost at capture. Down from up to four calls (including a sonnet call) per page.

Model cost moves to RAG

The only model spend is the RAG pipeline's contextual-retrieval step (task-31.3), run deliberately over the corpus and measured on the harness — not silently on every page view.

Haiku, configurable

When the pipeline does call a model, Haiku is the explicit configurable default via bergamot.models.fast; the smart role key is reserved but not user-exposed until a caller needs it.
