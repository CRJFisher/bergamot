🔎 RAG Pipeline

How re-downloaded public pages become retrievable answers — running after Temporal Topic Detection, the phased upgrade toward hybrid search, contextual chunking, and reranking, all measured against an evaluation harness.

re-download → TDT → chunk → embed → retrieve → rerank → generate

1Starting point

Capture is a zero-LLM metadata-only pipeline: it stores visit metadata (URL, title, timestamp, navigation graph) in DuckDB webpage_capture and reads no page content. Content is acquired downstream by re-downloading the stored public URL; pages behind a login wall fail to re-download and are excluded automatically. Temporal Topic Detection (TDT) runs first over the re-downloaded public corpus (embed → cluster); the RAG research tools come after. This pipeline starts from that re-downloaded public corpus and is free to re-run over all of it.

  • Input: the re-downloadable public subset — visits whose pages fail to re-download (auth-walled, dead) are excluded from clustering and retrieval and remain as trail/metadata only.
  • Ordering: TDT first, then RAG; both run over the same re-downloaded public corpus and share one local embedding model.
  • Chunking / embedding / retrieval / reranking: none yet — all introduced by the phases below.
  • Parent document: the re-downloaded page's extracted main-content markdown (a separate encrypted, brotli-compressed cache tier, populated by default as pages are re-downloaded), keyed by page_session_id; may be unavailable for login-walled or dead pages.
Re-download fidelity caveat. A re-downloaded page is not guaranteed to equal the page as viewed — dynamic/JS-rendered content, dead links, paywall/consent drift, A/B variants, and edits over time all diverge. Citations reference the URL and metadata, not a byte-for-byte snapshot; drift is surfaced via fetched_at + content hash + HTTP status.

2Target pipeline

The upgrade adds structure-aware chunking with contextual situating text, hybrid (dense + BM25) retrieval fused by Reciprocal Rank Fusion, cross-encoder reranking, and parent-document expansion — with every stage gated behind an evaluation harness.

3Build order (by ROI)

#PhaseWhat & why
AEvaluation harnessGolden dataset + metrics (Recall@k, MRR, nDCG, context precision/recall). Build first so every later change is measurable.
DHybrid searchLanceDB-native dense + BM25/FTS fused via Reciprocal Rank Fusion. High impact, low cost.
CChunking + Contextual RetrievalStructure-aware chunks with 50–100 tokens of LLM-generated situating context, plus parent-document retrieval. ~35% fewer retrieval failures (49% with BM25).
ERerankingCross-encoder / hosted reranker over top-N. ~67% fewer failures when stacked on contextual + hybrid.
BClean ingestionHeuristic main-content extraction (Trafilatura-style) to cut boilerplate before chunking.
GEmbedding model selectionChoose by measured Retrieval@k on the real corpus — not headline MTEB scores.
FQuery transformationHyDE, multi-query, routing — optional, behind config.
HGeneration-time surfaceCitations, context ordering, and a small-corpus short-circuit (<200K tokens → whole corpus in prompt).

4Key techniques

Contextual Retrieval

An LLM writes 50–100 tokens of chunk-specific context, prepended before both embedding and BM25 indexing — so a chunk knows which page and topic it belongs to.

RRF fusion

Reciprocal Rank Fusion merges dense and BM25 result lists into one ranking. LanceDB-native, no tuning weights.

Parent-document retrieval

DuckDB links each chunk to its page; a chunk hit returns the full page for richer context.

Small-corpus short-circuit

Under ~200K tokens, skip retrieval entirely and put the whole corpus in the prompt.

5Explicitly deferred (YAGNI)

  • GraphRAG — entity graphs & community summaries, for corpus-wide sensemaking later.
  • Agentic RAG — multi-hop reasoning, only if it becomes core.
  • Self-RAG — reflection tokens require custom model training, out of scope.
  • CRAG — corrective RAG with web-search fallback, revisit only if quality lags.
Principle: measure first (Phase A), then add the cheapest high-impact retrieval improvements before touching generation. Each phase is justified by a measured reduction in retrieval failures, not by novelty.
