🌐 Browser Extension

A lightweight Chromium MV3 capture layer. It records browsing metadata only — the visit's title/URL/timestamp and the cross-tab navigation graph — then posts metadata-only visits to the VS Code backend over HTTP. No page content is captured; all intelligence lives downstream.

ModuleResponsibility
content.tsInjected into every page at document_end. Reads the visit's title and URL, and reports the visit metadata on load and on SPA navigation. Retries on a cold service worker.
background.tsThe session authority. Owns the tab-history store; listens to all tabs / webNavigation events; serializes mutations through an operation chain; routes messages.
core/data_collector.tsPure functions that build the visit metadata: create_visit_data().
core/tab_history_manager.tsFunctional store of Map<tab_id, TabHistory>; mints group_id session IDs; tracks referrer chains.
core/tab_history_persistence.tsPersists the store to chrome.storage.session so it survives MV3 service-worker restarts.
core/message_router.tsDispatches getReferrer and sendToPKMServer; attaches session metadata to outgoing visits.
core/server_discovery.tsProbes ports 5000–5009, checks /status for the "bergamot" marker, caches the winning URL.
core/api_client.tsThin fetch POST wrapper (JSON body, no retry — the caller handles that).
core/configuration_manager.tsResolves config from test mock port, window.PKM_CONFIG, or defaults to http://localhost:5000.

2The session graph

The background service worker is the single source of truth for how visits relate. It mints a group_id once per tab (or inherits the opener's), tracks the previous URL as the referrer, and only attaches this canonical metadata at send time — avoiding races with a cold service worker.

3Visit payload & transport

Communication is a single HTTP POST — there is no native messaging. The extension discovers the backend by probing a small port range and verifying a service marker.

AspectDetail
EndpointPOST /visit (and GET /status for discovery)
DiscoveryProbe ports 5000–5009; accept the one whose /status returns service "bergamot"; cache it.
Body{ url, title, page_loaded_at, referrer, referrer_timestamp, tab_id, group_id, opener_tab_id } — metadata only, no page content.
ReliabilityContent script retries up to 20× (100 ms apart) to wake a cold MV3 service worker.
PermissionsTrimmed manifest: tabs, activeTab, storage, webNavigation.
No ML, no content in the extension. The browser side captures metadata only — title/URL/timestamp plus the session graph. It never reads or transmits page content. Content acquisition (re-download), classification, and storage happen in the VS Code backend. This keeps the extension fast and its permission surface minimal.
