🧩 VS Code Extension

The backend host. It activates the ingest server, durable queue, and LLM processing workflow; owns both storage backends (DuckDB + LanceDB); and spawns the MCP server. This is where capture becomes knowledge.

vscode/src · extension.ts activate() · ~60 TypeScript modules

1Activation

On activation, extension.ts wires the whole system together in order:

  • Config — resolve the LLM provider from VS Code settings (bergamot.llmProvider, defaulting to the Claude subscription via the Claude Agent SDK); an OpenAI API key (bergamot.openaiApiKey) is optional and only used when the provider is openai.
  • Databases — DatabaseManager.initialize_all() opens DuckDB and LanceDB (with local all-MiniLM-L6-v2 384-dim embeddings).
  • Ingest server — ServerManager.start() binds the first free port in 5000–5009 and writes it to ~/.bergamot/port.json.
  • Commands — CommandManager.register_all() registers webpage search, the hover provider, and the filter-metrics command.
  • MCP server — MCPServerManager.start_deferred(2000) spawns the standalone MCP subprocess after 2 s (non-blocking).

3Reception: durable ingestion

The server acknowledges the browser immediately, then processes asynchronously — no visit is lost on restart.

StageWhat happens
POST /visitHash url:page_loaded_at → session ID; decompress zstd; validate against a Zod schema.
InboxWrite the visit to {globalStorage}/visit_inbox/{id}.json (durable) before returning 200.
QueueVisitQueueProcessor drains the inbox in batches (size 3 or 1 s timeout) with retry.
CleanupOnce the visit is persisted to DuckDB, its inbox JSON file is removed. Orphans are reloaded on startup.

The three LLM prompts that drive it:

  • CONTENT_PROCESSING_PROMPT — strip ads/nav/footers, return clean Markdown.
  • ANALYSIS_PROMPT — produce { title, summary, intentions[] } for a single page.
  • TREE_INTENTIONS_PROMPT — re-derive per-page intentions using full navigation-tree context.

5Navigation trees

Visits are organized into trees — one per browsing session — using the referrer chain captured by the browser extension. A page with a known referrer is attached as a child of the tree containing that referrer; a page without one starts a new tree. Whenever a tree changes, its intentions are recomputed with the whole tree as context, so each page's purpose is understood relative to the session it belongs to.

Single-writer discipline. Only the extension writes to DuckDB. Every other consumer (MCP server, external scripts) reads through the HTTP query API, which keeps the embedded database safe from concurrent access.
