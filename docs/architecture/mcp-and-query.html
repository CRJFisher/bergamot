🔌 MCP & Query Layer

How AI agents and scripts reach the knowledge base. A standalone MCP server provides six tools; a read-only HTTP API backs the relational ones while the MCP server reads vectors directly.

mcp_server_standalone.ts · /query/* · stdio transport

1Topology

The MCP server runs as a separate subprocess spawned by the extension. Because DuckDB is single-writer, the MCP server cannot open it directly — relational tools proxy over HTTP to the extension's own server, while vector tools read LanceDB directly.

3HTTP query API

The same Express server that ingests visits also serves read-only queries. External scripts can hit these directly — the extension acts as the gateway to DuckDB.

EndpointPurpose
GET /statusHealth check + { service: "bergamot" } identity marker (used by browser discovery).
POST /visitIngest a captured visit (zstd content). Covered in VS Code Extension.
GET /query/visit_by_url?url=Exact-URL lookup of the most recent visit.
GET /query/page_by_title?title=Fuzzy title + content search.
GET /query/tree?tree_id=All pages in a navigation tree, with analysis.
GET /query/recent_trees?limit=Most recently modified trees.

4Discovery & security

  • The extension writes its chosen port to ~/.bergamot/port.json; the MCP subprocess reads it to find the relational API.
  • CORS is pinned to chrome-extension:// origins (and origin-less callers like curl/scripts); ordinary web pages are blocked.
  • Request body limit is 50 MB to accommodate compressed page content.
  • The MCP subprocess receives OPENAI_API_KEY, STORAGE_PATH, and DUCK_DB_PATH via environment variables.
Why proxy relational queries? DuckDB is embedded and single-writer. Rather than risk a second process opening the database file, the MCP server asks the extension — which owns the writer — over HTTP. Vector reads are safe to do directly, so those skip the hop.
