Cluster representations and the deterministic labeler

Step 5 turns one HdbscanRaw { labels[], probabilities[], exemplar_indices } into per-cluster RepresentedCluster[] + ClusterLabel[]: each cluster gets a representative page, a frozen representative vector, and a five-field label bundle that recomposes into a display string — with no LLM and no window-relative c-TF-IDF. Noise (-1) gets no representative. Persistence (36.6) and orchestration (36.9) come next; this stage produces in-memory objects only.

The one sentence

Three aligned arrays — labels[i] ↔ vectors[i] ↔ visits[i] — are read by row index to build, per cluster, a representative page (the eom exemplar, else a select_medoids fallback), a frozen L2-normalized mean vector, and five label fields stored separately so a pure compose_display_label() recomposes the display string and a later LLM can consume the bundle.

Where 36.5 sits — between the fit and persistence

Barrel hygiene — representations.ts is NOT re-exported from index.ts

select_medoids comes from clustering-tfjs, the same native TensorFlow chain that keeps cluster_window out of the barrel. So representations.ts follows the same rule; only the new types (ClusterLabel) are exported from index.ts. The deterministic labeler imports nothing native and could be exported, but it is colocated under labeling/ and reached through the same direct import for one clean boundary.

The correctness crux — one row index, three parallel arrays

The representative page and the frozen vector

A

Representative page — eom exemplar, else a lazy select_medoids fallback

The representative is exemplar_indices.get(label) — the densest-core page eom defines. select_medoids(X, labels, metric:'cosine') (the member closest to the cluster mean) is called lazily, only when a cluster lacks an exemplar. Under v1 defaults every cluster has one, so the medoid path is defensive — but AC #1 and §10 require the named function for the leaf case.

tdt/src/representations.ts (new) · select_medoids from clustering-tfjs (Phase 3)
B

Frozen representative vector — float64 fixed-order mean, then L2-normalize, then freeze

The representative vector is the L2-normalized mean of member vectors, accumulated in float64 in ascending index order with one float32 truncation — the discipline already in page_vectors.ts's mean_pool. It is then FROZEN: read now for ranking, and banked as the input the Phase-4 tracker's Hungarian match needs.

C

Noise (-1) has no representative

A label of -1 is "a page in no project" — it produces no RepresentedCluster, no representative page, no vector, no label bundle. Its persistence (a member row with is_noise = TRUE) is 36.6's job, not this stage's.

// exemplar (eom, densest-core) is the representative; select_medoids is the
// lazy fallback for the leaf / no-exemplar case (AC #1, plan §10).
function representative_index(
  label: number,
  exemplar_indices: Map<number, number>,
  medoid_of: (label: number) => number,   // closes over a lazily-computed select_medoids result
): number {
  const exemplar = exemplar_indices.get(label);
  return exemplar !== undefined ? exemplar : medoid_of(label);
}

// FROZEN representative vector: float64 mean over members in ASCENDING index
// order (IEEE-754 add is non-associative — order is the determinism contract),
// then L2-normalize, then one float32 truncation. The Phase-4 tracker's input.
function representative_vector(member_indices: number[], vectors: PageVector[]): Float32Array {
  const dim = vectors[member_indices[0]].vector.length;
  const acc = new Float64Array(dim);
  for (const i of [...member_indices].sort((a, b) => a - b))   // fixed order
    for (let d = 0; d < dim; d++) acc[d] += vectors[i].vector[d];
  // divide by member count, L2-normalize acc, truncate once → Float32Array (frozen)
}

Why scope reads "react.dev +2 sites"

The 5 members span three distinct registrable domains. With more than one, the format is "<primary> +<N> sites", N = distinct − 1 (here 2); a single-domain cluster reads just "react.dev".

site_name is never used — it is often-NULL <head> metadata; the URL's registrable domain is the always-present signal.

The label bundle — separate fields, one pure compose()

keyphrases — deliberately corpus-INDEPENDENT, not c-TF-IDF

Keyphrases come from the cluster's own member titles only: lowercase + NFC, tokenize on non-alphanumeric (\p{L}\p{N}), drop stopwords and tokens shorter than 3, count term frequency, take top-k by (count desc, token asc).

Because they depend on this cluster's titles alone, not the surrounding window, the same enduring project keeps the same keyphrases as its neighbors change — window-relative c-TF-IDF would drift, hostile to the cross-window stability tracking needs.

keyphrases + representation_version are the seam for a later fixed-corpus pass if measurement shows it is needed.

Decisions to confirm before implementation

Decision #1 — registrable domain: the tldts library, not a heuristic confirm

Add tldts@6.1.86 as an explicit tdt dependency. Offline, deterministic, already hoisted. getDomain('https://docs.google.com/x') → google.com; foo.co.uk correct; localhost → null.

A true eTLD+1 (every subdomain groups as one) needs the Public Suffix List; a "last two labels" heuristic is wrong for co.uk. This is the one new dependency.

Confirm: the new dependency vs a hand-rolled heuristic.

Decision #5 — the scope string shape and the display_label template confirm

scope = primary domain alone when one distinct domain, else "<primary> +<N> sites" (N = distinct − 1), with the domain distribution sorted by (count desc, domain asc). site_name is not used — it is often NULL/junk; the registrable domain is the always-present signal. The display_label template is "<headline or keyphrases> — <scope>", e.g. "React — Hooks reference — react.dev +2 sites".

Confirm: the scope string shape and the display_label template.

Settled decisions (built as described, no confirmation needed)

Decision #2 — the index-alignment contract

Assert, don't assume. raw.labels[i] ↔ vectors[i] ↔ visits[i] are aligned by row index — the same array fed to the distance matrix. exemplar/medoid indices index into it; represent_clusters and label_cluster assert length-equality and resolve indices directly to page_session_id + vector.

Decision #3 — select_medoids is lazy

Call it only when a cluster lacks an exemplar. Under v1 defaults (eom + store_exemplars) every cluster has an exemplar, so the medoid path is defensive — but AC #1 and §10 require the named cosine-medoid library function (member closest to cluster mean, metric:'cosine') for the leaf / no-exemplar case.

Decision #4 — the frozen vector is pure JS

float64 fixed-order mean → L2-normalize → one float32 truncation, mirroring page_vectors.ts. It is FROZEN: the Phase-4 cross-window tracker's Hungarian-match input, banked now.

Decision #7 — module placement & barrel hygiene

New files representations.ts, labeling/deterministic_labeler.ts, labeling/llm_naming_seam.ts (+ colocated .test.ts); ClusterLabel in types.ts. representations.ts is NOT re-exported from the barrel (its select_medoids import pulls the native tf chain); only the new TYPES are exported, and 36.9 imports the stage directly.

Net effect

After 36.5, every cluster carries a recognizable representative page, a frozen vector that de-risks tracking, and a recomposable label bundle — deterministic, offline, zero-LLM.

The only open choices are the tldts dependency (#1) and the scope/label string shape (#5).
