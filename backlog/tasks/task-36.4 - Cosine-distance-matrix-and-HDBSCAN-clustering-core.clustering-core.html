The clustering core: a precomputed cosine matrix and one TensorFlow-backed HDBSCAN fit

The only stage that touches clustering-tfjs: build a dense precomputed cosine-distance matrix, run one HDBSCAN fit through a TensorFlow.js backend, return raw { labels, probabilities, exemplar_indices }. Representations, the labeler, and persistence are later subtasks — this stops at HdbscanRaw.

The one sentence

Because the page vectors arrive L2-normalized, the cosine-distance matrix is one line — D[i][j] = clamp(1 − dot, 0, 2), zeroed diagonal — built in plain float64 JS, then truncated to float32 inside the library.

HDBSCAN's fit runs through a TensorFlow.js backend, so a backend is REQUIRED at runtime; results are bitwise-deterministic per backend, and the algo_version records exactly which backend ran.

The one-stage data flow — all clustering-tfjs isolated here

Why one stage owns every library touch

Isolating all clustering-tfjs contact in cluster_window.ts keeps the rest of @bergamot/tdt library-agnostic, so a future library swap or API-changing version bump is a single-file edit — and the camelCase ↔ snake_case translation lives here and nowhere else.

Bundle boundary — the clustering stage is NOT in the @bergamot/tdt barrel

The index.ts barrel is bundled into the VS Code extension by esbuild (the embed pass does a value import from @bergamot/tdt), and cluster_window's clustering-tfjs import pulls the native TensorFlow / node-pre-gyp chain — re-exporting it breaks the production bundle (scripts/bundle.mjs).

So the barrel stays bundle-safe and the clustering stage is imported directly by its orchestrator (36.9), which owns externalising the native deps into the VSIX — the native chain enters only at the 36.9 wiring.

The cosine-distance math — one line, because vectors arrive normalized

Determinism — per backend, pinned by installing exactly one

What stays true about determinism

The bitwise test earns its place: it regression-locks within-backend stability, verified byte-identical across two runs on both native tfjs-node and pure-JS cpu.

The upstream anchors stay load-bearing — a stable ORDER BY page_loaded_at, page_session_id (36.3) fixes MST tie-breaking, and fixed-order float64 segment pooling (36.3) fixes the vectors that feed D.

The HDBSCAN fit and the snake_case quarantine

The verified API is snake_case, so the one call site translates the library's snake_case outputs into TDT's HdbscanRaw shape — the only place this translation lives.

new tdt/src/cluster_window.ts  ·  the ONLY clustering-tfjs call; runs through the tf backend; camelCase↔snake_case quarantined here
// The single library touch-point. Imports clustering-tfjs; nothing else in
// @bergamot/tdt does. fit() runs through whichever tf backend is installed.
import { HDBSCAN } from "clustering-tfjs";
import type { DistanceMatrix, HdbscanRaw } from "./types";
import type { HdbscanConfig } from "./config";

// AC #6: a descriptive failure when the dependency is absent/unloadable,
// not a cryptic "undefined is not a constructor". A tf BACKEND is required too;
// reframe_clustering_error matches BOTH backend-absent strings (see below):
//   "No TensorFlow.js backend available"  — only if NO @tensorflow/* resolves
//   "No backend found in registry"        — the string tdt ACTUALLY hits, since
//      tfjs-core resolves but no compute backend (tfjs-node) is installed.
if (typeof HDBSCAN !== "function") {
  throw new Error(
    "clustering-tfjs HDBSCAN export is missing or unloadable — " +
    "install clustering-tfjs and one @tensorflow/* backend (tfjs-node).",
  );
}

export async function cluster_window(
  D: DistanceMatrix,
  config: HdbscanConfig,
): Promise<HdbscanRaw> {
  const model = new HDBSCAN({
    metric: "precomputed",        // cosine is not native; D is the only path
    min_cluster_size: config.min_cluster_size,  // default 3 (pages)
    min_samples: config.min_samples,            // default 5, DECOUPLED
    cluster_selection_method: config.method,    // 'eom' — defines exemplars
    cluster_selection_epsilon: config.epsilon,  // default 0.0
    store_exemplars: true,         // required for exemplar_indices_
  });

  await model.fit(D);          // fit-only · tf.topk + tf.maximum in one tf.tidy

  // snake_case (library) → snake_case (HdbscanRaw). Quarantined HERE.
  return {
    labels: model.labels_,
    probabilities: model.probabilities_,
    exemplar_indices: model.exemplar_indices_,  // Map<clusterId, rowIdx>
  };
}
new tdt/src/cluster_window.ts  ·  built ourselves in float64 — both guards run here, before the dot loop
// AC #1: dense (n,n), zero diagonal, symmetric, clamped to [0,2].
// Vectors are L2-normalized (Stage 2), so cosine_sim = dot, dist = 1 - dot.
// We accumulate in float64; the library re-tensors D to float32 (tf.tensor2d).
import type { PageVector, DistanceMatrix } from "./types";

export function build_cosine_distance_matrix(
  vectors: PageVector[],
  max_samples: number,
): DistanceMatrix {
  const n = vectors.length;

  // GUARD 1 — page-count ceiling (AC #3): reject BEFORE the O(n²) allocation.
  if (n > max_samples) throw new Error(
    `${n} pages exceeds max_samples=${max_samples}; windowing must subdivide`);

  // GUARD 2 — dimension uniformity: one-time O(n) sweep. A ragged window would
  // let the dot loop read past an array end (→ NaN) and silently poison HDBSCAN,
  // so a mismatched-length vector fails loudly here instead.
  const dim = n > 0 ? vectors[0].vector.length : 0;
  for (let i = 0; i < n; i++) if (vectors[i].vector.length !== dim)
    throw new Error(`page ${vectors[i].page_session_id} has dim ` +
      `${vectors[i].vector.length}, expected ${dim}.`);

  const D: number[][] = Array.from({ length: n }, () => new Array(n).fill(0));
  for (let i = 0; i < n; i++) {
    const vi = vectors[i].vector;
    for (let j = i + 1; j < n; j++) {
      const vj = vectors[j].vector;
      let dot = 0;                      // float64 accumulator (number)
      for (let k = 0; k < vi.length; k++) dot += vi[k] * vj[k];
      const d = Math.min(2, Math.max(0, 1 - dot));
      D[i][j] = d; D[j][i] = d;     // write both → symmetric
    }
    D[i][i] = 0;                  // forced-zero diagonal (never the ≈0 dot)
  }
  return D;
}
guards tdt/src/cluster_window.ts  ·  AC #6 error reframing — matches BOTH backend-absent strings
// AC #6: re-frame the library's backend-absent error so the fix (install a host
// TensorFlow backend) is obvious; pass anything else through unchanged.
// TWO distinct strings cover the same root cause:
export function reframe_clustering_error(err: unknown): Error {
  const message = err instanceof Error ? err.message : String(err);
  if (
    // fires ONLY when no @tensorflow/* resolves at all:
    message.includes("No TensorFlow.js backend") ||
    // the string tdt ACTUALLY hits: tfjs-core resolves, but no compute
    // backend (tfjs-node) is installed, so a tf op fails later with:
    message.includes("No backend found in registry")
  ) {
    return new Error(
      "cluster_window: no TensorFlow.js compute backend available. The host must " +
      "install @tensorflow/tfjs-node. Original: " + message,
    );
  }
  return err instanceof Error ? err : new Error(message);
}

Scope boundary — this task stops at HdbscanRaw

Step 4 produces only the distance matrix and the single isolated fit — not representations or the frozen representative vector, medoids, the labeler (36.5), persistence (36.6), or orchestration and run keying (36.9).

The output is the in-memory HdbscanRaw object, not persisted cluster rows; algo_version is recorded here but consumed later.

Design decisions

Decision #0 — keep cluster_window OUT of the package barrel

Direct import from the orchestrator, never the barrel. esbuild bundles index.ts into the extension; if it re-exported cluster_window, the embed pass's value import would drag the native TensorFlow / node-pre-gyp chain into scripts/bundle.mjs and break it. The barrel exports types and pure-JS helpers only; 36.9 imports the clustering stage directly and externalises the native deps in the VSIX.

Decision #1 — build D ourselves vs reuse a library distance call

Build it ourselves in float64. Cosine is not a native HDBSCAN metric, so precomputed is the only cosine path (AC #1): D[i][j] = clamp(1 − dot, 0, 2), zero diagonal, symmetric. The library then does tf.tensor2d(rows), truncating our float64 D to float32 internally — still deterministic.

Decision #2 — install TensorFlow?

Yes — native @tensorflow/tfjs-node in the vscode host. The production host that runs clustering in its off-event-loop worker installs native tfjs-node for the ~11× boost; the tdt library depends on clustering-tfjs@^0.6.1 + @tensorflow/tfjs-core (read backend name only, no ops), with tfjs-node as a test-time devDependency. darwin-x64 prebuilt installs fine.

Decision #3 — the algo_version backend slot

Record the real backend. Final value algo_version = hdbscan-1#clustering-tfjs@<version>#<backend>, e.g. hdbscan-1#clustering-tfjs@0.6.1#tensorflow. The version is read by resolving clustering-tfjs's install dir + fs.readFileSync of its package.json (a plain require('clustering-tfjs/package.json') is blocked by its exports field); the backend via require('@tensorflow/tfjs-core').getBackend() after the first fit → 'tensorflow' for native.
