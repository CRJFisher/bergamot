Page vectorisation — TDT embeds re-downloaded pages into one vector each

One pure module turns each re-downloadable public page into a single L2-normalized vector — the unit HDBSCAN clusters on. TDT is the first content consumer: it reads already-extracted page content, embeds with its own local model, and depends on no RAG pipeline and no LanceDB.

The independence property this step realizes

TDT consumes already-extracted CorpusContent — it never re-downloads, never parses raw HTML, and never re-classifies fetch outcomes. Pages are re-downloaded eagerly per visit and cached upstream (task-39.2 / CachedCorpus); auth-walled / paywalled / dead / non-HTML pages are excluded at the corpus boundary and never appear here. This is where TDT's "no task-31 dependency" becomes real: it embeds whole pages for clustering with its own injected local model, over the same content RAG uses for retrieval — no chunking, no contextual prefixes, no LanceDB.

Determinism anchors — AC #4 (verified by test)

The vector is a pure function of (content, repr, config, pinned model). Five anchors make it bitwise-stable regardless of fetch/processing order: NFC + whitespace collapse, code-point (surrogate-safe) slicing, sequential in-order embedding (an explicit for…await, never Promise.all), fixed-order float64 accumulation for every sum (IEEE-754 addition is non-associative, so iteration order is load-bearing), and exactly one float32 truncation at the final store.

Cache, store & invalidation

Storage decision — resolved: encrypted DuckDB, LanceDB rejected

Page vectors live in the encrypted DuckDB store through the VectorStore port — LanceDB was evaluated and rejected because it cannot be encrypted at rest while searchable, and content-derived vectors are sensitive. DuckDB serves similarity search natively via array_cosine_similarity over fixed-size FLOAT[dim] columns. That search path is deferred to RAG (task-31), which shares the same encrypted store and embedding space; TDT itself only reads cached vectors and computes its own in-memory cosine distance matrix in 36.4.

The module surface — page_vectors.ts

shipped tdt/src/page_vectors.ts
// Pure module: imports only types + ports. No network, no DuckDB, no RAG.
// Consumes already-extracted content from the task-39.2 corpus read path;
// never re-downloads, never parses raw HTML, never re-classifies fetch outcomes.

// types.ts
export type PageRepr = "title_plus_lead" | "main_content_extract";

export interface PageContent {   // projection of CorpusContent
  page_session_id: string;
  title: string;          // "" (never null) when absent; the no-text guard handles it
  content: string;        // already-extracted main-content markdown
}

// config.ts — defaults are 36.7-sweep starting points, not hardcoded behaviour
export interface PageVectorConfig {
  lead_chars: number;                 // 1000 · title_plus_lead lead length (code points)
  segment_chars: number;              // 1600 · code points per segment
  dispersion_min_mean_cosine: number; // 0.35 · below → multi-topic → medoid
  degenerate_norm_epsilon: number;    // 1e-6 · the single near-zero floor
}

/**
 * Pure (content, repr, config) × embed → vector | null. Same text + pinned model
 * → byte-identical vector, regardless of processing order. null = excluded
 * (no extractable text, or truly degenerate even after the medoid fallback).
 * @throws RangeError if the embedder returns inconsistent dims across segments.
 */
export async function build_page_vector(
  content: PageContent,
  embed: EmbedFn,
  repr: PageRepr,
  config: PageVectorConfig,
): Promise<PageVector | null>;

/**
 * Cache-aware: vector_store.get → on miss build_page_vector → put. Returns the
 * BARE vector (the cache unit), not a PageVector — a hit cannot reconstruct
 * low_confidence. An excluded page returns null and caches nothing.
 * CALLER INVARIANT: repr MUST match the version encoded in embedding_model_id;
 * the key omits repr, so keep the two in lockstep at the call site.
 */
export async function resolve_page_vector(
  content: PageContent,
  embed: EmbedFn,
  vector_store: VectorStore,
  embedding_model_id: string,
  repr: PageRepr,
  config: PageVectorConfig,
): Promise<Float32Array | null>;

/**
 * Collapse repeat same-URL visits within one nav tree to one clustering unit.
 * Keeps the FIRST row per (tree_id, url) in input order; input is already sorted
 * ascending (compute_windows contract), so "first" == earliest. Does not sort.
 */
export function dedupe_visits(visits: VisitRow[]): VisitRow[];

The acceptance criteria, as shipped

1

Reads content, not the network — one L2-normalized vector via the injected EmbedFn

Consumes PageContent projected from the task-39.2 corpus (CorpusContent). No FetchedPage, no fetch, no HTML parse, no outcome classification, no dependency on RAG chunk vectors or LanceDB.

AC #1 · page_vectors.ts → build_page_vector · types.ts → PageContent
2

Cached in topic_page_vector; a model or representation change invalidates

resolve_page_vector folds the repr version into embedding_model_id, so a model or representation change is a clean miss. Stores only the vector + repr via VectorStore.put in the encrypted DuckDB store.

AC #2 · page_vectors.ts → resolve_page_vector · ports.ts → VectorStore
3

Guards: dispersion → medoid, degenerate → fallback, no-text → excluded

Dispersion (mean pairwise cosine over units < dispersion_min_mean_cosine) → medoid segment, low_confidence. Pooled-norm collapse → medoid fallback. Empty text or final norm < ε → null.

AC #3 · page_vectors.ts → build_page_vector
4

Determinism — same page + pinned model → bitwise-identical vector

NFC + whitespace collapse, code-point slicing, sequential in-order embedding, fixed-order float64 accumulation, one float32 truncation. The test embeds the same page in different orders and asserts byte equality.

AC #4 · page_vectors.ts (normalize_text, mean_pool)
5

Repeat same-URL visits within a tree are deduped before clustering

dedupe_visits keeps the first row per (tree_id, url) in input order; the same URL in a different tree is kept.

AC #5 · page_vectors.ts → dedupe_visits
6

Unit tests cover the guards, caching/invalidation, and determinism

Colocated page_vectors.test.ts: medoid fallback, ε fallback and exclusion, empty-text null, model-id-change cache miss, and the order-independence determinism assertion.
