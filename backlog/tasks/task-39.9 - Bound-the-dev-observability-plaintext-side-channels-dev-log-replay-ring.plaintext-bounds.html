Bound the dev-observability plaintext side-channels

Two dev-only artifacts write visit URLs to disk in plaintext, outside the encrypted metadata store: the tail-able dev-log.jsonl (and its .1 rotation) and the replay ring of recent full visit JSONs under captures/. This work brings both inside the privacy boundary — the forget cascade deletes the dev log, a packaged install can never write either artifact silently, and the writes are named honestly in the threat model with a documented size bound.

vscode/src/right_to_forget.tsAC#1 — wholesale delete, idempotent
/** Deletes the plaintext dev-log.jsonl and its rotation wholesale.
 *  Coarse but real: no per-line rewriting. Returns the count removed. */
function sweep_dev_log(storage_base: string): number {
  let removed = 0;
  for (const name of ["dev-log.jsonl", "dev-log.jsonl.1"]) {
    try {
      fs.unlinkSync(path.join(storage_base, name));
      removed++;
    } catch { /* absent — nothing to delete */ }
  }
  return removed;
}

// inside forget(), beside the replay sweep:
  const files_removed = options.storage_base
    ? sweep_replay_captures(options.storage_base, selector) +
      sweep_dev_log(options.storage_base)   // dev log is unconditional
    : 0;
why wholesale, not per-line

The dev log is append-only JSONL with no index; selectively rewriting only the forgotten URLs' lines would be fragile and is explicitly out of scope. Wholesale deletion is coarse — a forget by one URL removes the whole log — but it is real deletion, and the log is a dev-only artifact that re-creates itself on the next stage write. The replay sweep still matches by selector; only the dev log is deleted unconditionally.
