Bounding the dev-observability plaintext side-channels

Two dev-only artifacts write visit URLs to disk in plaintext, outside the encrypted metadata store: the tail-able dev-log.jsonl (with its .1 rotation) and the replay ring of recent visit JSONs under captures/. Both now sit inside the privacy boundary — the right-to-forget cascade deletes the dev log, a packaged install can no longer write either artifact silently, and the writes are named honestly in the threat model with a documented size bound.

how it fits

sweep_dev_log in the forget() flow

vscode/src/right_to_forget.tswholesale delete, idempotent, returns count
/** Deletes the plaintext dev-log files (dev-log.jsonl and its rotation
 *  dev-log.jsonl.1) under the storage base, wholesale. The JSONL log
 *  interleaves stage lines from every visit, so a forget cannot
 *  selectively remove one URL's lines without rewriting the file —
 *  wholesale deletion is the right trade-off for a dev-only artifact.
 *  Returns the count of files removed (0, 1, or 2). */
function sweep_dev_log(storage_base: string): number {
  let removed = 0;
  for (const name of [DEV_LOG_FILENAME, `${DEV_LOG_FILENAME}.1`]) {
    try {
      fs.unlinkSync(path.join(storage_base, name));
      removed++;
    } catch { // Missing or already removed — nothing to do. }
  }
  return removed;
}

replay = selector-matched · dev log = wholesale

The two sweeps differ deliberately. sweep_replay_captures reads each captures/*.json and deletes only those matching the selector. sweep_dev_log takes no selector: the append-only JSONL interleaves lines from every visit, so it is deleted whole and re-created on the next dev_log() append. Both no-op cleanly when their files are absent.

the interface

Why dev_log_files_removed is a separate field

vscode/src/right_to_forget.ts — interface ForgetReportone field added, not a merged count
export interface ForgetReport {
  /** Page sessions resolved by the selector. */
  page_session_ids: number;
  /** Distinct URLs the forget swept. */
  urls: number;
  /** Whether the content-cache cascade ran. */
  content_cache_swept: boolean;
  /** Selector-matched plaintext dev-replay files (captures/) removed. */
  files_removed: number;
  /** Dev-log plaintext files (dev-log.jsonl and .1) deleted wholesale. 0, 1, or 2. */
  dev_log_files_removed: number;
}
why not fold it into files_removed

The two counts have different semantics — files_removed is selector-matched replay captures; dev_log_files_removed is a wholesale 0/1/2. Merging them would hide that distinction and break the command layer's "nothing matched" guard, which must check dev_log_files_removed === 0 independently: a forget that deletes only the dev log still did something, so it must not report "nothing forgotten."
