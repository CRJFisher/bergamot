task-39.2 · privacy-core · keystone subtask

Re-download content fetcher & the content read path

Page content is no longer stored at browse time. It is obtained later by re-downloading the public URL the metadata row recorded, through a stealth headless browser running as an anonymous, cookie-free visitor. The login wall does the filtering: authenticated and paywalled pages fail to render content and drop out automatically. This page maps where content comes from now versus before, the stealth browser and why it does not weaken privacy, the pure classifier that is the privacy mechanism, the redownload/ module map, and the corpus every downstream consumer reads.

the shift

Where page content comes from — then vs. now

A request for a page's content used to read a zstd-compressed BLOB written into DuckDB at capture time. Now the same request triggers a live re-download of the stored URL: a stealth headless browser navigates to it as a stranger, the result is classified, and either public content or a structured "unavailable" comes back. No content BLOB is read; read_capture() and get_webpage_capture_bytes are deleted.

BEFORE · removed

Stored-BLOB read

Capture sent HTML; it was zstd-compressed into content_compressed and read_capture() decompressed on demand. Content was the durable source of truth — and a privacy liability on disk. Both reader functions are now deleted; 39.1 drops the column.

NOW · built by 39.2

Stealth re-download on demand

Capture sends only url/title/timestamp/graph. A patchright headless browser re-downloads the URL as an anonymous visitor when content is needed, classifies the outcome, and emits fidelity metadata. Metadata is the durable source of truth; content is derived and transient.

the fetch mechanism · AC #1

A stealth headless browser, fetching as a stranger

Re-download runs through patchright — a stealth-patched, drop-in replacement for Playwright — driving headless Chromium. Stealth hides the automation signals (navigator.webdriver, CDP leaks, the headless user-agent) that anti-bot defenses use to block headless browsers, so genuinely public pages re-download as content instead of being lost to an interstitial. A plain HTTP fetch would also miss JS-rendered pages whose real content arrives via client-side scripts; the browser renders them.

why stealth does not weaken privacy

Stealth widens coverage of public pages only — it defeats anti-bot detection, never authentication. The browser context carries no cookies and no user profile (no storageState, no persistent profile), so every page is fetched as an anonymous stranger. Authenticated and paywalled pages still answer with a login redirect, a 403, or a paywall and are excluded. The login wall remains the privacy filter; stealth just makes sure the truly-public pages on the other side of it actually come back.

Browser pool browser_pool.ts

Owns one shared headless Chromium, launched lazily on first content request. A single ephemeral cookie-free context is reused; each fetch gets a fresh page that is always closed. Images, media, and fonts are aborted per request — only text and <meta> are needed. The browser is closed on server shutdown.

Polite egress politeness_gate.ts · AC #6

Re-download is a generic async scheduler: a per-host minimum interval (2 s), global (2) and per-host (1) concurrency caps, and exponential backoff with jitter. Only transient failures — timeout, 5xx, 429 — retry (up to 3 times), and a Retry-After header overrides the computed backoff.

the conceptual heart · AC #2

The login wall is the privacy filter

There is no "is this page sensitive?" heuristic to trust or get wrong. The browser re-downloads and the pure classify_fetch(observation) reads what came back, returning a discriminated FetchOutcome. A page is excluded because it would not re-download as public content for an anonymous visitor — not because its topic was judged. The classifier takes a serializable observation, so it is fully unit-testable without launching a browser.

the package

The redownload/ module map

The work lands as a new vscode/src/redownload/ package. Chromium coupling is isolated to two files; the classifier and the corpus contract are browser-free. The front door is corpus.ts — the interface TDT and RAG consume.

corpus.ts front door · contract

The ContentCorpus contract: get_content(id) re-downloads one page on demand and appends the fidelity record; iter_public_pages() yields only the ok subset, isolating per-page failures. The thing downstream depends on.

fetch_outcome.ts pure · the filter

The pure, browser-free classifier. classify_fetch + the discriminated FetchOutcome union + extract_markers_from_html. Where the login wall as privacy filter actually lives.

headless_fetcher.ts patchright

Drives a patchright page: navigate, settle, observe the final main-frame response, run the classifier, compute the content hash, parse <meta>. Never throws on a page-level failure — exclusions come back as outcomes.

browser_pool.ts chromium

The shared, lazily-launched headless Chromium with one ephemeral cookie-free context. The only other file that touches the browser. Blocks image/media/font requests; closes cleanly on shutdown.

politeness_gate.ts egress

A generic async scheduler: per-host interval, concurrency caps, backoff + jitter, Retry-After honouring. Knows nothing about browsers or outcomes.

content_hash.ts fidelity

SHA-256 hex of the re-downloaded HTML, so later drift (the same URL returning different content) is visible.

repointing · AC #5

The content read path, repointed at re-download

One HTTP endpoint serves content; the MCP tool is a thin proxy in front of it. The swap is at /query/capture_content: instead of decompressing a BLOB, it calls content_corpus.get_content(page_session_id) and returns the discriminated corpus entry — content for ok, a structured exclusion otherwise. If the re-download infrastructure itself fails (e.g. the headless browser cannot launch), the endpoint degrades to a 503 "unavailable" rather than an opaque 500.

read_capture + get_webpage_capture_bytes deleted

The stored-content reader and its dead byte-reader are removed entirely — no shim. The <meta> parse (read_metadata) is reused verbatim, now run on the re-downloaded page inside the fetcher rather than at capture time.

server_manager.ts — /query/capture_content (as built)verbatim
// Re-download the stored public URL on demand and serve its content.
// Auth/paywall/dead/non-HTML report unavailable — the login wall is the filter.
this.app.get('/query/capture_content', async (req, res) => {
  const page_session_id = String(req.query.page_session_id ?? '');
  if (!page_session_id) {
    res.status(400).json({ error: 'Missing page_session_id query parameter' });
    return;
  }
  try {
    const entry = await this.content_corpus.get_content(page_session_id);
    res.json(entry);                         // CorpusEntry | null
  } catch (error) {
    // Reaching here means the re-download infrastructure failed
    // (e.g. headless browser could not launch) — not a per-page exclusion.
    res.status(503).json({
      outcome: 'unavailable', page_session_id, reason: format_error_detail(error),
    });
  }
});
fidelity · AC #3 #4

What each fetch records: the webpage_fetch log

Every re-download — whether it yields content or not — appends one row to a new append-only DuckDB table, webpage_fetch. The row records the outcome, the fidelity triple, and any parsed <meta>. It stores no page content: the re-downloaded bytes are returned on demand and dropped. An encrypted on-demand content cache is a separate tier (task-39.3).

live re-download, every read · no cache in this tier

Each get_content call performs a real, side-effecting, politeness-gated headless navigation plus a webpage_fetch log write. There is no content cache here — the encrypted on-demand cache that avoids re-fetching is task-39.3. The persistence helpers are insert_webpage_fetch / get_latest_webpage_fetch in duck_db.ts, with WebpageFetchSchema in page_capture_models.ts.

the contract · AC #7

The corpus that TDT and RAG consume

The corpus is a named, documented interface — the re-downloadable public subset. get_content(id) returns a discriminated CorpusEntry (ok carries the content + metadata + fidelity; any other outcome carries a reason and no content; null means no stored metadata row). iter_public_pages() yields only the ok pages. Auth-walled and dead visits never enter it — they remain trail/metadata only. This is the single coverage boundary every downstream consumer inherits.

honest edges

Known limits, surfaced not hidden

SPA walls mounted after the settle window

Login and paywall detection is regex over the rendered HTML at the end of a bounded settle window (load + a 3 s cap). A wall that a single-page app mounts client-side after that window can slip through as ok. This is a fidelity limit, not a soundness one — the structured signals (password form, isAccessibleForFree:false, known containers) catch the common cases.

Chromium provisioning for a packaged extension — not yet wired

The headless browser (~150 MB) is downloaded out-of-band today; provisioning it for a packaged extension is a follow-up before release. Until then, a launch failure degrades to the 503 "unavailable" path rather than crashing the read.

fidelity caveat — represented, never pretended-away

A re-downloaded page is not guaranteed to equal the page as viewed: dynamic content, dead links, paywall/consent drift, A/B variants, edits over time. Citations reference the URL and metadata, never a byte-for-byte snapshot. The fetched_at + content_hash + http_status triple in webpage_fetch is how that divergence is surfaced.
