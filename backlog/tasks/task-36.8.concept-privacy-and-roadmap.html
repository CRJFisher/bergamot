Privacy guarantees & the decomposition into sub-tasks

The constitution forces a read/write asymmetry on every cluster surface. That asymmetry resolves the read-only-vs-read-write question, and the resolution decomposes into eight implementation sub-tasks (36.8.1–36.8.8) — seven of which ship the v1 launch path; the eighth (the VS Code webview) is the one deferred accessory. This task's own output is ADR 0001.

The read/write asymmetry every surface respects

Principle 8 — staging only, never canonical notes

Constitution principle 8 — inviolable (relaxable only by user amendment)
"Autonomous agents never write to canonical PKM notes. Agents write append-only to a quarantined staging area the user promotes by hand. Agent-authored content is clearly tagged. The deterministic source of truth is never mutated by an agent."

docs/constitution.md · governs the canonical-note boundary

The external landscape validates the staging quarantine

Nooscope queues AI output in SQLite then flushes to a vault inbox, "maintaining a human review gate before permanent integration"; Note Companion lands suggestions in a dedicated Inbox folder. bergamot.staging/ is the same quarantine pattern — its "human review gate" rationale is quoted in ADR 0001.

Metadata / encrypted-store invariants every surface respects

#InvariantWhat it forces on a surface
1 The metadata store is the durable source of truth and the syncable artifact (principle 6). Surfaces read derived metadata only; they never become a second source of truth or an un-forgettable copy.
2 Re-downloaded content lives in a separate quarantined, encrypted, scoped, deletable tier — never git-tracked, never the PKM repo. Two stores, two OS-keystore-backed DEKs; a surface never co-mingles them.
3 Staging is the privacy seam in write-back: staged stubs are plaintext markdown where the file-watcher sees them. Defense is quarantine-by-directory + never-canonical + auto-gitignore (*), not encryption — a staging dir inside a PKM/git repo would otherwise risk commit or sync despite principle 6.
4 Right-to-forget cascades (principle 4): forgetting by URL / origin / time-range deletes cluster memberships, page-anchored controls, AND derived staged stubs. Staged stubs are plaintext outside the encrypted stores, so the cascade runs a filesystem sweep (sweep_staged_stubs) matching primarily on the resolved forgotten page_session_id set, falling back to url/origin, and using the frontmatter window for a time-range forget. It also scrubs ledger entries of promoted-out stubs citing a forgotten page. The report grows two fields: cluster_controls_deleted + staged_stubs_removed.
never_cluster_origin survives a forget — by design

The forget cascade deletes page-anchored controls (suppress / rename, keyed on the forgotten page) inside the metadata transaction. never_cluster_origin controls deliberately survive — a block on a site is a preference, not page-derived state, so it is excluded from the count and from the delete.

Reads are clean by the privacy core's own design

The clusterable corpus is the re-downloadable public subset by design: auth-walled / dead pages are excluded from clusters, so a surface never risks exposing login-walled content. Reads are loopback-bound, per-extension capability-token authed (principle 7), over metadata-only tables — no page content, no re-download triggered by a surface.

The explicit read-only vs read-write decision

DirectionModeWhat is writtenConstraint
Toward the PKM read-mostly The note-stub only — write-only into bergamot.staging/. Append-only at the canonical boundary (per-file overwrite of un-promoted drafts permitted, guarded by the ledger + fingerprint gate). No reading PKM edits back as signal — a rename is not an approval; that feedback loop is explicitly out of scope.
Toward Bergamot's own state read-write Cluster-boundary curation — suppress / rename / never-cluster-origin. Writes to the topic_cluster_control table in the encrypted metadata store. In scope now, launch-blocking (constitution §3), keyed on the exemplar page + a content signature to survive run_id recomputes; suppress/rename are right-to-forget cascade targets, never_cluster_origin survives.
Stable identity — the concrete keying

A cluster's id is hash(run_id | local_label) and rotates every recompute, so a control row cannot key on it. Suppress/rename anchor on the cluster's exemplar page_session_id plus a content signature (NFC + lowercase of headline_title / scope / sorted keyphrases) as a secondary matcher; a control matches a cluster if either matches. never_cluster_origin keys on a registrable domain. Controls are applied in-memory inside cluster_reads, not SQL-joined. The note-stub filename uses the same lineage idea: ISO-week + a slug of the label, so a re-run of a thread overwrites its own stub rather than spawning a duplicate. (lifeline_id is the clean Phase-4 fix.)

The brittle trap to never conflate

Curation is a write-back control signal that ships now; PKM-edit-derived feedback is explicitly out of scope. The two must not be conflated — treating stub edits as curation would skirt the principle-8 boundary and is brittle (a rename is not an approve). Stubs flow out to staging; nothing flows back from PKM edits.

Decomposition — the eight implementation sub-tasks

Eight sub-tasks (36.8.1–36.8.8), each justified against the intention tree: UNDERSTAND (turn browsing into a queryable knowledge base) and SURFACE (push the projects the user is actually working on at a habit anchor). 36.8.1–36.8.7 are the v1 launch path and are done; 36.8.8 (the VS Code webview) is the one deferred accessory. The integration primitive is the blocking dependency for everything; this task's own output is ADR 0001.

Sequence 0 — blocking dependency (the primitive)
36.8.1 depends-on: nothing read-only done

Cluster read primitive (cluster_reads.ts)

Four pure (db, params) → JSON functions filtered to status='complete' live runs: list_clusters_in_range, get_cluster, list_clusters_for_page, window_coverage. Returns the label-bundle fields exactly — scope surfaced verbatim as the labeler's display string, members joined for url/title/page_loaded_at/probability/is_exemplar. Excludes representative_vector. page_status ∈ {clustered, noise, unseen} distinguishes processed-noise. Applies suppress/rename controls in-memory. Clamps via MAX_QUERY_LIMIT.

UNDERSTAND: the one queryable contract over the knowledge base; every surface depends on it.

36.8.2 depends-on: 36.8.1 read-only done

Four /query/cluster* routes + retire raw-tool scope

GET /query/clusters, /query/cluster, /query/clusters_for_page, /query/cluster_coverage over the existing relay (param validation, 400, MAX_QUERY_LIMIT clamp, res.json). Explicitly NOT /query/topic_* and NO MCP ListTools/CallTool cases. Plan §9 is rewritten to describe the primitive while preserving the separate Stage-1 visits_in_window bulk read (owned by TASK-36.9). Cluster tables added to the right-to-forget cascade.

contract + principle 12: retires the DB-shaped raw-tool scope cleanly with no half-built routes, without orphaning Stage-1.

Sequence 1 — backbone + actionability (the hero loop)
36.8.3 depends-on: 36.8.1 read-write → staging done

Note-stub renderer + staging writer (the backbone)

Render one markdown stub per cluster (headline_title → H1, scope verbatim, keyphrases → tags, member URLs → MoC links, exemplar pinned, one-line summary) into bergamot.staging/ via a pure renderer (note_stub.ts) + a filesystem writer (staging_writer.ts), agent-tagged frontmatter, auto-gitignore. Each member link embeds page_session_id + a percent-encoded URL in a <!-- bergamot:cite … --> comment the forget sweep matches on. POST /stage_cluster triggers it server-side.

SURFACE: the hero-loop deliverable, the PKM-native push surface, satisfying principle 8 by construction; the citation comment is the contract the forget sweep matches on.

36.8.4 depends-on: 36.8.3 read-write → staging done

Staging idempotency + right-to-forget filesystem sweep

Deterministic filename per lineage (ISO-week + slug(label)); a re-run overwrites its own un-promoted draft in place. A .bergamot-ledger.json gives promotion-safety: a known lineage whose file is gone is never recreated; a file absent from the ledger is never clobbered. A content fingerprint gate skips unchanged rewrites. The forget sweep matches primarily by the resolved forgotten page_session_id set (URL-independent), falls back to url/origin, uses frontmatter window overlap for time-range, and scrubs ledger entries of promoted-out stubs citing a forgotten page.

SURFACE (trust + principle 4): without idempotency, unstable run-local labels churn stubs and erode trust; without the keyed sweep, plaintext stubs escape the forget cascade.

36.8.5 depends-on: 36.8.2, 36.8.3, 36.8.7 read drives writes done

The bergamot-clusters skill

A SKILL.md + a dependency-free Node dispatcher at skills/bergamot-clusters/ (tracked source, symlinked into the gitignored .claude/skills/). Subcommands recent / page / cluster / coverage / stub / suppress / rename / block (and inverses) call the loopback routes only — no DB access. It answers in-context recall, DRIVES stub generation (cluster → stub → /stage_cluster), and is the host-agnostic driver for the launch-blocking control surface. Resolves clusters by a fresh id each turn (ids dangle across recomputes).

SURFACE + UNDERSTAND: the in-workflow actionability layer, the host-agnostic push vehicle, and the host-agnostic home for the launch-blocking control surface; cheapest surface.

36.8.6 depends-on: 36.8.5 read opt-in staging write done

Weekly cluster digest cadence

The weekly cadence is a /schedule routine (e.g. Monday 08:00 local) that runs recent --days 7 + coverage --days 7 and summarises into a short digest, optionally staging a weekly-review stub. The routine IS the cadence — retune the cron there. Quiet by design: pull-first and triaged, opt-in writes/notifications, and a quiet week produces no stub.

SURFACE: the host-agnostic push anchor for hosts without a panel. Pull-first with opt-in weekly write, per the notification-fatigue lesson: triaged, not a firehose.

Sequence 2 — launch-blocking control + deferred accessory
36.8.7 depends-on: 36.8.1 launch-blocking read-write → control done

Cluster-control table + write route

The topic_cluster_control table (encrypted metadata store) + POST /cluster_control(/delete), consumed by the skill so the launch-blocking control surface is host-agnostic. Suppress/rename anchor on the exemplar page + a content signature (survive recomputes); never_cluster_origin keys on a registrable domain. The route translates the on-screen cluster id into the stable anchor. never_cluster_origin is RECORDED now; the filter that excludes the origin from re-download / clustering input is wired by TASK-36.9. Suppress/rename are right-to-forget targets; never_cluster_origin survives.

SURFACE (constitution §3, launch-blocking): converts "surveilled" into "seen"; mandatory, not optional. Ships with the skill on the launch path.

36.8.8 depends-on: 36.8.2, 36.8.7 deferred · VS-Code host only deferred

VS Code webview cluster dashboard (NOT launch-blocking)

A net-new WebviewView/Panel: timeline + cluster cards + member drill-down + domain scope, consuming the primitive via port.json + token-authed fetch in the extension host, postMessage to a sandboxed CSP/nonce webview; an opens-on-launch activation. Optionally hosts the control affordances from 36.8.7 as one-click card buttons — a richer host, never their only route. The one accessory deferred past launch.

SURFACE (for VS Code users): the richest ambient-visibility accessory and a discoverable control host, but host-locked and off the launch critical path — built after the backbone + skill + control route prove the loop; resist any PKM-write affordance.

Sequencing & status at a glance

The decomposition in one line

One read primitive, then a PKM-native staging backbone driven by a host-agnostic skill, then a launch-blocking control surface that ships with the skill — with the VS Code webview as the one deferred accessory and ADR 0001 recording the read/write asymmetry. Every sub-task traces to UNDERSTAND or SURFACE, and no surplus surface is built (YAGNI): representative_vector stays hidden, raw /query/topic_* tools are never created, scope is surfaced verbatim, and PKM-edit feedback is out of scope.
