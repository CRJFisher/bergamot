task-39.1 · privacy-core · capture / schema / tests

Stop ambient content capture, reset the schema to metadata-only

Privacy is bergamot's organizing principle. The capture path stores browsing metadata only — never page content: visit id, URL, page-load timestamp, title, and the navigation/session graph. The browser stops reading page content entirely. Page content and its derived fields are obtained later by re-downloading the public URL as an anonymous, cookie-free visitor, where the login wall is the privacy filter. This is the contract for that change: what the capture pipeline does, the settled design decisions behind it, and the exact files that carry the work — read before any code is written.

the principle

The browser does not read the page at all

The point is not "read the page but do not store it." Reading a logged-in page's content at all would defeat the privacy model — the most private thing a user does is what they actually read, and the moment it is in memory it is a liability that demands an impossible "is this sensitive?" judgement. So the content script reads only what the tab already exposes without touching the document body: the URL and document.title. Nothing parses the page.

the login wall is the privacy filter — and it lives elsewhere

Content comes from re-download, not the logged-in browser

To understand a page, bergamot re-downloads it from its public URL as an anonymous stranger (task-39.2, shipped). A page that requires a login simply will not come back, so the private ones exclude themselves with no heuristic to trust. The logged-in browser is never the source of content; only the cookie-less re-downloader is. Every content-based judgement — auth, paywall, empty, redirect — happens there, on the re-downloaded bytes, never on what the user saw.

settled with the product owner

Four resolved design decisions

These are not open questions. Each was confirmed and is the cheapest correct way to honor the model under the no-surplus rule.

1

Title comes from the tab, not the HTML

The browser does not read page content at capture. Title is document.title, read from the tab; URL and load timestamp likewise. Nothing parses the document body.

Reading the logged-in page at all is the liability. The tab already exposes title/url/time without touching content.
2

The four meta columns are dropped, not nulled

site_name, author, published_at, lang leave webpage_capture entirely. Re-download's webpage_fetch log is the sole source of fidelity metadata.

Keeping them as perpetually-NULL columns is surplus. No-surplus per the constitution: a column that nothing fills should not exist.
3

The model variants collapse

content leaves the canonical PageActivitySession. With it gone, PageActivitySessionWithoutContent is identical to the base and is dropped; PageActivitySessionWithoutTreeOrContent becomes PageActivitySessionWithoutTree.

The "WithoutContent" distinction is meaningless once no variant carries content. The remaining axis is tree / no-tree.
4

The capture gate is deleted; incognito moves to the manifest

page_gate.ts (empty/auth/redirect) + gate_metrics.ts + the show_gate_metrics command are removed. Incognito refusal is added at the cheapest layer: "incognito":"not_allowed" in the manifest, so the extension never runs there.

Every gate check was content-based; auth/redirect filtering already moved to re-download (39.2). Today no incognito handling exists anywhere — the manifest flag adds it.
no backwards-compat shims (constitution)

This is a destructive change. No migration, no adapters, no kept-as-NULL columns, no tests propped up against the old contract. The store is reset to the metadata-only shape; callers are updated to the new pattern; obsolete code and fixtures are deleted outright.

the destructive reset

The webpage_capture shape, before and after

The store is recreated to the metadata-only shape — no migration. Eight columns leave: three compression columns and four <head>-derived fields. Five columns remain.

vscode/src/duck_db.ts — CREATE TABLE webpage_capturereset · no migration
// columns that LEAVE — content & its derived metadata
content_compressed BLOB NOT NULL,   -- zstd page bytes
content_encoding   TEXT NOT NULL,   -- codec marker, e.g. 'zstd'
original_byte_size INTEGER NOT NULL,-- decompressed size
site_name    TEXT,                  -- parsed from <head>
author       TEXT,                  -- parsed from <head>
published_at TEXT,                  -- parsed from <head>
lang         TEXT,                  -- parsed from <head>

// columns that REMAIN — browsing metadata only
page_session_id TEXT PRIMARY KEY,
url             TEXT NOT NULL,
title           TEXT,        -- from document.title (the tab), not parsed HTML
content_type    TEXT,
captured_at     TIMESTAMP NOT NULL
where the dropped fields live now

Content and author / site_name / published_at / lang are produced by re-download and recorded in the webpage_fetch table (task-39.2). The capture row holds the trail; the fetch log holds the fidelity metadata of whatever came back through the login wall. The two join on the URL.

dependency — why 39.2 had to land first

This task drops the stored content blob. The read path that served content must already point at re-download, or get_webpage_content returns nothing the moment the blob is gone. Task-39.2 repointed that read path and shipped first by design. With it in place, dropping the blob is safe.

done means

Verification checklist

  • A visit payload carries url + title + session graph — no content field, no base64 blob.
  • No @hpcc-js/wasm-zstd in the browser, no @mongodb-js/zstd in vscode; no WASM compile path; 'wasm-unsafe-eval' gone from the manifest CSP.
  • A fresh webpage_capture table has exactly five columns; no content/compression/meta columns exist.
  • page_gate.ts, gate_metrics.ts, and the show_gate_metrics command are gone; the extension declares "incognito":"not_allowed".
  • A test browses a page and asserts zero stored page content (AC #6); obsolete gate fixtures are removed.
  • read_metadata.ts still exists and is reachable from src/redownload/corpus.ts; only its capture-time call is gone.
  • Build and the full test suite are green with no shims kept to stay green.
