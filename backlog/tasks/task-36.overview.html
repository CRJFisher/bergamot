Temporal Topic Detection — windowed HDBSCAN clustering (micro tier)

Turn timestamped, passively-captured browsing into coherent projects — sets of highly-related pages — and surface one-off pages as noise rather than forcing them into a topic.

The one question this answers for the user

“What projects have I been working on, and which pages belong to each?”

The surface is split into two layers

Past persistence, exactly one thin integration primitive — a host-agnostic read API over the cluster + 36.5 label-bundle tables — touches the database; its natural home is the standalone Bergamot daemon. Every user-facing surface is a consumer of that one primitive, so surfaces ship independently and per-host. The likely shape, which 36.8 confirms: note-stub write-back (into a quarantined bergamot.staging/ directory, never canonical notes) as the PKM-native backbone, a Claude skill as the in-workflow actionability layer that also drives stub generation, and a VS Code webview as an optional rich-visibility accessory. These surfaces layer; they do not compete.

Parent acceptance criteria

#Criterion
1The @bergamot/tdt package clusters a real window of re-downloaded public pages into project groups end-to-end and exposes them through a thin host-agnostic read API, without blocking capture; auth-walled / failed-re-download visits are excluded.
2TDT embeds pages with its own model and has no build-time or runtime dependency on the RAG pipeline (task-31).
3Clustering is deterministic and reproducible — same captures + pinned model produce identical clusters, verified by a regression test.
4One-off pages are surfaced as noise rather than forced into clusters; per-window coverage / noise rate is queryable.
5Operating parameters are selected by a validation sweep on real data and persisted as config, not hardcoded.
6The design draft remains the canonical reference and stays in sync with what ships.
7Every cluster/persistence store joins the right-to-forget cascade in vscode/src/right_to_forget.ts, with cascade tests extended.
