Data inputs & the privacy model

Capture stores metadata only, never content. Content comes from re-downloading the stored public URLs — and the login wall is what decides which pages can be clustered at all.

Capture stores metadata only — never page content

The re-download funnel — public pages become clusterable, the rest stay trail-only

The login wall is the privacy filter

The privacy mechanism, stated once

There is no content classifier deciding what is “private.” A page that sits behind a login simply fails to re-download — so it has no embedding and falls out of clustering automatically. The wall does the filtering; the system never has to judge content.

The re-download fidelity caveat

Re-downloaded bytes ≠ what was viewed

Unlike a captured snapshot, re-downloaded bytes are not guaranteed to equal the page as viewed: JS-rendered content, dead links, paywall/consent drift, A/B variants, and edits all diverge — and a page may re-download on one run and fail on the next. Page vectors are stable only relative to a given re-download.

The run therefore records fetch fidelity (fetched_at, http_status, content hash) so drift and changes in corpus membership are visible across re-clusters.
