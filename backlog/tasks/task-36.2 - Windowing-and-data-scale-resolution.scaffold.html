Windowing: turning the visit stream into bounded frames HDBSCAN can run over

Slice the timestamped visit stream into time windows that each stay under the HDBSCAN sample ceiling, deterministically, so the same captures always produce the same frames.

file tdt/src/windowing.ts branch tdt depends on 36.1 guard max_samples 4000 default calendar month (UTC)

Why this step exists

The load-bearing invariant

The window default (calendar month) is a convenience; the real guarantee is the hard page-count guard. A calendar boundary does not bound a count — a single bursty month can blow past 4000 pages. So a calendar window that overflows must subdivide, and the bounds it actually used must be recorded per window.

The algorithm, end to end

The subdivision decision tree — which strategy fires, and when

When a window overflows the guard, subdivide_order = ["gap","half_month","iso_week"] is tried in order. Each strategy splits the window; every resulting sub-window is then re-checked against the guard and recursively subdivided with the next strategy if still oversized.

Termination is the trap

Gap-split can fail to reduce size when visits are uniformly dense (no large gaps). Calendar bisection must therefore always reduce the span — and the recursion bottoms out at the smallest configured calendar unit (ISO week). If a single ISO week still exceeds max_samples, that is a real signal (an extreme burst) the implementer should surface, not silently loop. Guard every recursive call with a strictly-shrinking measure.

Feel the split — adjust the burst, watch which strategy fires

A toy month of visits. Slide the burst density up until the page count crosses max_samples, then run subdivision. Watch gap-split fire on a gappy stream, and watch bisection take over when the burst is gapless.

The determinism contract, concretely

"Pure function of (timestamps, config)" is not a vibe — it is five concrete rules. Break any one and re-runs diverge, which breaks reproducible cluster runs (parent AC #3) and the future stateless tracker.

The one-line acceptance test for AC #2

compute_windows(v, cfg, a, b) called twice on the same inputs yields JSON.stringify(out1) === JSON.stringify(out2) — byte-identical bounds, byte-identical ordering, every run.

Resolving the real data scale (AC #1)

Before fixing the window default, the plan requires querying the live distribution of page_loaded_at per month and recording the result. The default tightens to 14 days only if a typical month routinely exceeds a few thousand pages.

What to implement in windowing.ts

Public surface first, then the internal helpers. Keep everything a pure function — no I/O, no clock, no globals.

tdt/src/windowing.ts — public surface (snake_case per repo convention)
import { VisitRow } from "./types";
import { WindowConfig } from "./config";

// One per emitted frame. The skip variant carries the reason so the
// caller surfaces "not enough data yet" instead of spurious singletons.
export type WindowSignal =
  | { kind: "window"; start: string; end: string; visits: VisitRow[] }
  | { kind: "skip"; start: string; end: string; reason: "not_enough_data" };

// Main entry. visits MUST be pre-sorted by (page_loaded_at, page_session_id).
// range_start inclusive, range_end exclusive. Pure: same args -> same output.
export function compute_windows(
  visits: VisitRow[],
  config: WindowConfig,
  range_start: string,
  range_end: string,
): WindowSignal[];
  1. iter_calendar_windows(range_start, range_end, config) — yield [start,end) UTC bounds as ISO strings. For unit:"month", step month-by-month; for unit:"days", step config.days at a time from range_start. Pure string/UTC math, no Date round-tripping that changes formatting.
  2. slice_visits(visits, start, end) — return the contiguous sub-slice where start <= page_loaded_at < end by lexicographic string compare. Since visits is sorted, this is a binary-search lower/upper bound, not a filter.
  3. sparse check — if slice.length < config.min_window_visits, push a skip signal and continue. Do this before the guard.
  4. subdivide(slice, start, end, config, order_index) — if slice.length <= max_samples, emit one window. Otherwise apply subdivide_order[order_index] (gap | half_month | iso_week), then recurse on each sub-window with the next strategy index for the bisection fallbacks.
  5. split_at_gaps(slice, max_samples) — compute inter-visit gaps, cut at the largest first (stable tie-break), producing sub-windows whose bounds are the actual first/last timestamps + the half-open boundary. Pure function of the timestamps.
  6. bisect_calendar(start, end, unit) — half-month or ISO-week midpoint as a UTC ISO string; the guaranteed-terminating fallback. Recurse until a sub-window fits or the smallest unit is reached.
  7. record actual bounds — every emitted window carries the actual start/end used (post-subdivision), not the calendar bounds, so the run record (AC #3) and future tracker can thread irregular frames.
tdt/src/windowing.test.ts — the three tests AC #5 requires (colocated)
// 1. boundary determinism (AC #2)
expect(json(compute_windows(v, cfg, a, b)))
  .toEqual(json(compute_windows(v, cfg, a, b)));

// 2. overflow subdivision (AC #3): a 6k-page month emits multiple
// windows, each <= max_samples, with recorded actual bounds.
const out = compute_windows(dense_month(6000), cfg, a, b);
expect(out.every(w => w.kind !== "window" || w.visits.length <= cfg.max_samples)).toBe(true);

// 3. sparse-window skip (AC #4): < min_window_visits -> skip, no singleton
const s = compute_windows(make_visits(3), cfg, a, b);
expect(s.find(w => w.kind === "skip")?.reason).toBe("not_enough_data");
Boundaries TDT does NOT use

tree_id (navigation trees) is carried as provenance metadata only — it is never a window boundary, because a single project deliberately spans many trees. The clustering unit is the page visit, and the only time signal is page_loaded_at.
