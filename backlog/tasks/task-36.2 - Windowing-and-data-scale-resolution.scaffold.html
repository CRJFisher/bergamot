Windowing: the visit stream sliced into bounded frames HDBSCAN runs over

compute_windows turns a timestamped visit stream into a flat list of WindowSignals — each emitted frame stays under the HDBSCAN sample ceiling, sparse frames are skipped, and identical inputs always yield byte-identical output.

What was built

export type WindowSignal =
  | { kind: "window"; start: string; end: string; visits: VisitRow[] }

The load-bearing invariant

The month default is a convenience; the real guarantee is the hard page-count guard. A calendar boundary does not bound a count — one bursty month can blow past 4000 pages. Such a window subdivides, and each emitted frame carries the actual post-split start/end (not the calendar bounds), so the run record threads irregular frames.

The pipeline, as implemented

The termination crux — why both children keep the full strategy list

The one design decision worth studying: when subdivide_window recurses, what strategy list does each child receive? The wrong choice either loops forever or stops splitting too soon. The implementation distinguishes a successful split from a no-progress path, and passes a different list in each case.

tdt/src/windowing.ts :184–219 — the recursion, verbatim
const strategy = remaining_strategies[0]!;
// strategies_tail is passed on no-progress paths (null or degenerate split):
// the list strictly shrinks, guaranteeing termination.
// On a successful split, both children receive remaining_strategies so a
// still-oversized half can retry the same strategy.
const strategies_tail = remaining_strategies.slice(1);

let split_ms: number | null = null;
if (strategy === "gap")        split_ms = find_largest_gap_ms(visits);
else if (strategy === "half_month") { /* candidate, in-bounds check */ }
else if (strategy === "iso_week")   { /* candidate, in-bounds check */ }

if (split_ms === null) {                              // no progress
  return subdivide_window(start_ms, end_ms, visits, config, strategies_tail);
}

const left  = visits.filter(v => parse_iso_ms(v.page_loaded_at) < split_ms!);
const right = visits.filter(v => parse_iso_ms(v.page_loaded_at) >= split_ms!);

if (left.length === 0 || right.length === 0) {      // degenerate → no progress
  return subdivide_window(start_ms, end_ms, visits, config, strategies_tail);
}

return [                                            // successful split
  ...subdivide_window(start_ms, split_ms, left,  config, remaining_strategies),
  ...subdivide_window(split_ms, end_ms,   right, config, remaining_strategies),
];
The exhaustion floor

When remaining_strategies is empty and the window is still over the guard (e.g. every visit shares one timestamp, so no split exists), the window is emitted as-is with a console.warn rather than looping. A degenerate dense burst is surfaced as a real signal, never silently dropped. Tested directly: five visits at an identical timestamp emit one over-size window and trigger the warning.

The strategy ladder — gap, then calendar seams

subdivide_order defaults to ["gap", "half_month", "iso_week"]. The order is config, not hardcoded — tests drive subsets like ["half_month","iso_week"] or ["iso_week"] to isolate each rung.

StrategySplit pointTie-break / guardWhy this rung
gap page_loaded_at of the right visit of the largest inter-visit gap. larger gap wins; then lower right-visit ms; then lower page_session_id. Returns null if < 2 visits or all share one timestamp. A long silence is the most likely seam between two projects — cutting there keeps coherent work together.
half_month the 16th of the window's month, 00:00 UTC. used only if strictly inside (start, end); otherwise treated as no-progress. A solid multi-week sprint has no large gap to cut; a fixed calendar seam always halves a month.
iso_week the Monday 00:00 UTC of the ISO week containing the window midpoint. used only if strictly inside (start, end). Tested to always land on a Monday (getUTCDay() === 1). The finest calendar cut — the recursion's floor before exhaustion.
Gap-split records actual bounds (AC #3)

Two bursts split at the second burst's first visit: the test asserts the left frame's end and the right frame's start both equal that visit's page_loaded_at — the recorded bounds are the real seam, while the outer start/end stay pinned to the calendar window. No visit is lost or duplicated across the split.

Feel the split — adjust the burst, watch which strategy fires

A toy month of visits. Slide the burst density up until the page count crosses max_samples, then run subdivision. A gappy burst is cut at its silences (gap-split); a uniform-dense burst has no gap, so calendar bisection takes over.

The determinism contract, as built

"Pure function of (timestamps, config)" is five concrete rules, each backed by a test. All arithmetic runs on epoch milliseconds parsed from ISO — there is no lexicographic string comparison anywhere in the module.

Correction from the scaffold plan

The pre-build plan proposed lexicographic string range checks and a binary-search slice. The built module instead parses every timestamp to epoch ms and uses Array.filter for range membership — simpler, and it lets parse_iso_ms reject non-UTC offsets at the door rather than mis-sorting them. Determinism is preserved because parsing is total and deterministic.

The window default is fixed before the live distribution is measured, with the scale-check query recorded as a JSDoc comment above DEFAULT_WINDOW_CONFIG so re-tuning is a config change, not a code change.

Status of AC #1

The live DuckDB is encrypted at rest and held read-write by the extension, so the query runs through the HTTP broker, not a direct CLI connection. Personal single-user browsing stays well under max_samples = 4000 in any month, so the count guard is the rare-burst safety valve, not the common path — the month default is retained. Pasting actual monthly counts into the task notes once the extension is running is the recorded follow-up; if the busiest month exceeds ~4000, tighten unit to days/14.
