4 · Threat-model mapping — which gap each task closes

Adversary B — hostile local process
Another process on the same machine talks to the local server.
40Capability token on /visit, /query/*, /dev_signal. Today only CORS — any local process can read re-downloaded content & inject visits. "Largest open gap."
Adversary A — offline / file-level access
Someone reads files on disk while the extension isn't guarding them.
39.8Plaintext visit-inbox JSON — the encrypted store's plaintext front door. "Largest remaining plaintext side-channel."
39.9Dev-log + replay ring write URLs in plaintext — but behind a default-off gate.
39.7Linux without a keyring silently degrades key wrapping to obfuscation — no user signal today.

6 · What to do next — the honest recommendation

1
Highest VALUE next move: start TDT — task-36.1 (scaffold @bergamot/tdt). This is the critical path to the hero loop and is fully unblocked. Nothing in the hardening track needs to finish first.
2
Highest-PRIORITY privacy obligations: 40 and 39.8. Both HIGH, both independent, both close the two "largest gap" items in the threat model. They can run in parallel with TDT — they touch the server and storage layers, not the TDT package.
3
Then the medium hardening: 39.9 and 39.7, and verify-and-close 34. None are urgent; sequence them around the higher-value work.

Bottom line: doing the hardening track does not advance the hero loop, and starting TDT does not require finishing hardening — but hardening is required before a privacy-credible release (constitution: privacy is the core organizing principle; principle 7 is inviolable). Pick by goal: ship value → TDT; close the privacy promise → 40 then 39.8.
